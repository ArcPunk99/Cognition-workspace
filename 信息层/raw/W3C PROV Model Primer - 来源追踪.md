# W3C PROV Model Primer · 来源追踪

研究问题：「我是不是在重复造轮子？」本次只查其中一部分：从一个判断往回找，怎样记清用了哪份资料、谁参与、它从哪个旧版本修订而来？见 [[Personal Workspace Handoff V0.4#阶段 A：问题出现|问题出处]]、[[Personal Workspace Handoff V0.4#阶段 B：资料发现|Knowledge Graph / Truth Maintenance 线索]]。

资料由 W3C Provenance Working Group 于 2013-04-30 发布，文献类型为 Working Group Note。收录于 2026-11-22。下面是 Codex 对来源追踪这条线索的阅读指引。[W3C 原文（固定版本）](https://www.w3.org/TR/2013/NOTE-prov-primer-20130430/)

## 值得读的三处

1. **§2.3，改稿的例子。** 一次修改用到了旧稿和勘误表，产出的是新稿。它回答的是「一次活动实际用了哪些输入，又生成了什么？」对照工作台，可以用这段检查：仅仅收进 Raw 的材料，和形成某条判断时确实用过的材料，能否区分？[原文 §2.3](https://www.w3.org/TR/2013/NOTE-prov-primer-20130430/#usage-and-generation)
2. **§2.5，两段连读，留意末句。** 同一次编辑中，人可以担任编辑，两份输入可以分别充当待改文稿和补充内容。PROV 可以表达角色，角色的具体含义由使用方定义。它回答的是「同一次工作里，怎样分别记录谁整理、谁审阅、谁确认？」对照 MS-001，可检查确认记录是否能指到你认可的那句话。[原文 §2.5](https://www.w3.org/TR/2013/NOTE-prov-primer-20130430/#roles)
3. **§2.6，重点读第二段。** 每次修订的结果可以有自己的标识，并指回上一版。它回答的是「怎样既找到新判断的来历，又能读到旧判断当时的内容？」回到工作台，还要另问一句：哪次人工决定让新判断正式取代旧判断？[原文 §2.6](https://www.w3.org/TR/2013/NOTE-prov-primer-20130430/#derivation-and-revision)

这份资料能用来比较现有模型如何表达来源、角色与修订。至于某个现成工具能否在日常操作中自动留下这些记录，还需要该工具本身的证据。
