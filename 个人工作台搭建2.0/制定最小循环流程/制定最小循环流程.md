本对话是这个任务的讨论现场。在对话里逐个讨论各模块的功能点。

起点：已抽出七个环节，待讨论后收敛。

1. 启动 Project（功能点已定）
2. 在讨论里开展 Task
3. 发出并完成 Action
4. 暴露 Trigger（注：Trigger 是意图表的一种状态，不另开表）
5. 人确认
6. 回流
7. 沉淀 Artifact

## 已确认：启动 Project

1. 创建极轻：一个标题、一段说明，就可以启动。
2. 启动时立下总体目的，后面的意图和任务都围着它转。
3. 未来上平台，就是数据库里一条记录，不必一上来搭复杂结构。
4. 现在不必预先建本体；如果做的是 case 工作台，本体才需要拿出来讨论。
5. 库级有项目总表，一行一个 Project，启动即加一行。字段：稳定 ID、标题、说明、启动时间、状态（进行中 / 暂停）、项目目录。
6. 读写规则为库级一份，各项目共用。

## 已确认：记录与看板

1. 取消「当前记录」这种手写汇总，不再靠人维护项目进展页。
2. 数据放在各环节自己的表里：库级有项目总表，项目里有任务清单、意图表，后面判断、产物、日志各有各的表。每个 Task 另有独立目录，目录里放 Task 记录和行动表。
3. 打开一个项目，就是按它的 ID 把相关表合在一起看。这就是未来前端看板的项目视图。
4. 不设单独的项目记录处页；目的在项目总表，读写规则在库级。
5. 操作日志记动作，不记全文。写必记，读默认不记；系统自动追加，只追加不改。
6. 前端看板是视图，只读上述数据，不另存一套状态。现在不开发前端。数据层按前端能直接接来设计。

## 已确认：意图域

1. 意图是人主动输入，或与 agent 对话后觉得需要去做的事，对应信息缺口或认知缺口。它不是结论。结论在信息域，管「事情是怎样的」；意图管「需要去做什么」。
2. 意图可能转化成行动；有具体行动才会有目标，这个目标是这次 Action 的目的。
3. Trigger 不另开表，就是意图表里状态为「候选」（尚未推进）的行。
4. 意图表字段：意图本身；状态（候选 / 已转化行动 / 已完成）；若已转化或已完成，则有目标。另有：稳定 ID、所属项目 ID、来源或依据、形成时间。
5. 单轮循环：意图出现后先以 Trigger 入表；识别到人正在确认、对话仍在继续，或 Trigger 被确认，则转化为行动并生成目标；人说 OK，这次行动完成，输出产物片段，本轮结束。这不等于整个 Task 结束。
6. 判断、产物不写入意图表，各自成表，用意图 ID 关联。产物仍须人确认后才入库。

当前这条意图已入表，见 [意图表](../意图表.md) I-001。状态为已转化行动，目标是把三域定下来。

## 已确认：信息域

1. 表做索引，库放原文；表里不塞全文。库只存原文，不另记一套状态。
2. 原始资料和结论分两张表。Raw 到达后不改原文；结论必须人确认后才能入库，未确认的结论不入结论表。
3. 原始资料表放在项目内的 `原始资料` 文件夹中。
4. 原始资料表字段：稳定 ID、所属项目 ID、形态（文件 / 对话等）、标题或简述、来源、到达时间、库中位置；需要时挂意图 ID。
5. 结论表字段：稳定 ID、所属项目 ID、结论本身（事情是怎样的）、依据（关联的 Raw ID）、形成时间；需要时挂意图 ID。结论表尚未建。
6. 那份理论框架 MD、以及本对话过程，都是原始资料，已入表为 R-001、R-002。R-002 原文仍在本对话，暂未落库。
7. 资料入口：可通过复制不同 Agent 的会话链接、会议录音、文章批注等方式，承载行动过程并沉淀为资料资产。收到后分三步，不混在一起：（1）先把原文落入 `原始资料` 库，并在原始资料表加一行，这是 Raw，到达后不改原文；（2）提炼可以做，但不和原文放在一起进 Raw，提炼只是候选判断，人确认后才入结论表；（3）再根据这批信息做一次关联判断，提给人确认：它是什么类型的信息，是否对着某个已有意图，是否发生在某个 Task 里，是否是某个 Trigger 转化成的 Action，或用来印证已经发生过的行动。资料到了，不等于已经判断完，也不自动改意图状态，不自动当产物入库。

见 [原始资料表](../原始资料/原始资料表.md)。

## 已确认：行动域

1. Task 是更高一层的工作单元，围着一个 Task 目标，承载数个执行过程，直到这个目标实现。
2. Action 是一次具体的执行过程，不能无限制做大。
3. Task 的目标会转化成一条或多条行动对策，每条对策就是一个 Action 的目标。
4. 每个 Task 建一个独立目录，目录里放 Task 的字段记录，以及该 Task 下的行动表。意图表、原始资料库仍在项目级，用 ID 关联，不在每个 Task 里再复制一套。
5. Task 字段：稳定 ID、所属项目 ID、标题、目标、状态（待启动 / 进行中 / 暂停 / 已完成）、形成时间。项目级有任务清单，一行一个 Task。
6. Action 字段：稳定 ID、所属 Task ID、目标（那条行动对策）、状态（进行中 / 已完成 / 暂停）、执行过程（或过程记录在目录中的位置）、形成时间；需要时挂意图 ID。
7. 某个 Action 结束，不等于 Task 结束。Task 目标是否实现，须经人确认。
