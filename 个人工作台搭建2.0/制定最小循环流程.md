# 制定最小循环流程

目的：把个人工作台的最小循环流程定下来，并在对话里逐个讨论各模块的功能点。

所属项目：P-003 个人工作台搭建2.0（见 [项目总表](../项目总表.md)）

起点：已抽出七个环节，待讨论后收敛。

1. 启动 Project（功能点已定）
2. 在讨论里开展 Task
3. 发出并完成 Action
4. 暴露 Trigger（注：Trigger 是意图表的一种状态，不另开表）
5. 人确认
6. 回流
7. 沉淀 Artifact

本对话是这个任务的讨论现场。

## 已确认：启动 Project

1. 创建极轻：一个标题、一段说明，就可以启动。
2. 启动时立下总体目的，后面的意图和任务都围着它转。
3. 未来上平台，就是数据库里一条记录，不必一上来搭复杂结构。
4. 现在不必预先建本体；如果做的是 case 工作台，本体才需要拿出来讨论。
5. 库级有项目总表，一行一个 Project，启动即加一行。字段：稳定 ID、标题、说明、启动时间、状态（进行中 / 暂停）、项目目录。
6. 读写规则为库级一份，各项目共用。

## 已确认：记录与看板

1. 取消「当前记录」这种手写汇总，不再靠人维护项目进展页。
2. 数据放在各环节自己的表里：库级有项目总表，项目里有任务清单、意图表，后面判断、产物、日志各有各的表。
3. 打开一个项目，就是按它的 ID 把相关表合在一起看。这就是未来前端看板的项目视图。
4. 不设单独的项目记录处页；目的在项目总表，读写规则在库级。
5. 操作日志记动作，不记全文。写必记，读默认不记；系统自动追加，只追加不改。
6. 前端看板是视图，只读上述数据，不另存一套状态。现在不开发前端。数据层按前端能直接接来设计。

## 已确认：意图域

1. 意图是人主动输入，或与 agent 对话后觉得需要去做的事，对应信息缺口或认知缺口。它不是结论。结论在信息域，管「事情是怎样的」；意图管「需要去做什么」。
2. 意图可能转化成行动；有具体行动才会有目标，这个目标是这次 Action 的目的。
3. Trigger 不另开表，就是意图表里状态为「候选」（尚未推进）的行。
4. 意图表字段：意图本身；状态（候选 / 已转化行动 / 已完成）；若已转化或已完成，则有目标。另有：稳定 ID、所属项目 ID、来源或依据、形成时间。
5. 单轮循环：意图出现后先以 Trigger 入表；识别到人正在确认、对话仍在继续，或 Trigger 被确认，则转化为行动并生成目标；人说 OK，这次行动完成，输出产物片段，本轮结束。这不等于整个 Task 结束。
6. 判断、产物不写入意图表，各自成表，用意图 ID 关联。产物仍须人确认后才入库。
