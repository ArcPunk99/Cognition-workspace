# 个人工作台

这里用来推进手头的项目。一个想法可以从一页开始。打开项目时，能看清想做成什么、哪项任务正在推进；回到任务时，能接着上次的判断往下做。

## 怎么用

1. **有了想法，开一个项目。** 用项目名建立目录和同名入口页，写下一句想解决的问题或想做成的事。按 [[Schema#项目内的存放位置|项目目录约定]] 建好信息层、任务层和产物层。方向还在探索时，先写清眼下最想弄清的问题。
2. **有了具体的事，就在任务层展开。** 每项任务有自己的目录和同名任务页。填好「所属项目」和「状态」，用几句话写下为什么做（目的）、这次想做到什么（目标）、下一步做什么。任务层是过渡区，工作草稿、对话中值得回看的片段和待确认的里程碑都可以先留在这里。
3. **回来接着做时，先看项目页。** 项目入口页和它的 Bases 视图（`.base`）放在项目根目录。打开入口页的进度表，点任务名就能看到上次停在哪儿。
4. **你确认一版阶段成果，就把该版本存入产物层。** 从任务页链接到具体版本；同一任务下一阶段再获确认时，两个版本都保留。任务可以继续推进，等你确认收尾后再改为「已完成」。

## 怎么留下判断的来路

信息层承担认知层的职责。任务对话中的片段值得作为原始材料留存时，连同出处存入 `信息层/raw/`；其中某条判断经你确认后，单独记入 `信息层/认知里程碑/`，链接到形成它的材料或对话段落。

1. **收资料时记出处，读到哪里就记到哪里。** 在项目页留下研究问题的原话，把收到的材料放进 `信息层/raw/`。Raw 链到这个问题，保留原件或来源 URL 和获取日期。你说「我只读了第二节」，就在 Raw 标「部分已审」，正文写「已读第 2 节，其余未审」。如果只收到一份交接材料，人工审阅情况未知，就留空。
2. **留下判断时，说清每处引用起什么作用。** 在 `信息层/认知里程碑/` 为你确认的那句话建页，记谁确认、何时确认或从哪里能找到确认记录。逐条说明资料的哪一段支持、反驳或限定了什么。同一份资料的两段话可以起不同作用。实际例子见 [[MS-001 认知形成过程必须完整可追溯]]，页内可直达 Handoff 的确认句。
3. **你决定改目标或策略时，留一条变更记录。** 在项目页追加原表述、新表述、触发判断的链接、调整理由和确认人及时间。接手执行的任务链到这条记录。若讨论还停在「要不要改」，先保留原目标。

## 让判断和任务相互推进（设计讨论稿）

**讨论 → 交接材料（Handoff）→ 来源材料（Raw）→ 已确认的判断（Milestone）→ 任务（Task）→ 阶段成果（Artifact）→ 人工确认 → 更新判断。** 更新后的判断可以继续指导下一轮任务。已有明确目标的任务也可以直接开工。

- **接续讨论。** 在能写文件的对话里，你可以让 Codex 把 Handoff 放进对应项目的 `信息层/raw/`。保留交接材料本身，注明它来自哪次讨论、何时形成、当时在解决什么问题。Handoff 是整理过的摘要；引用对话原话时要能追溯到原文。其他工作资料也可以作为 Raw。
- **留下判断。** 你说「这条留下」，一句话就可以成为一条独立引用的 Milestone。Codex 也可以从 Handoff 提取你已明确确认的判断，连回对应 Raw。确认不清楚的建议留作候选，等你决定。按设计，可以在 Bases 里筛选项目的 Milestone，点开来源回看。
- **带着依据做事。** 任务引用用得上的 Milestone，需要时顺着链接读 Raw。正在推敲的版本留在任务目录；经你确认的阶段版本进入产物层，仍可追到当时采用的依据。
- **用结果检验判断。** 如果验证结果与原判断冲突，Codex 把两者和依据一起列给你。你可以接受这版交付，也可以进一步决定修订哪条判断。你确认了新判断，就新增一条 Milestone。如果你同时明确它取代了哪条旧判断，再记下替代关系，保留原判断和原依据。

项目里验证过的方法，先留在项目里。哪些内容值得整理进共享知识库，由你另外指定。

笔记属性、三种记录的写法和仍在讨论的字段提案，见 [[Schema]]。
