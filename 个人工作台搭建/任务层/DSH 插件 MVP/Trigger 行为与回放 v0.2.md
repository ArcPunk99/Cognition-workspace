# 工作台 Trigger 实验 · v0.2

设计来源：[[Project 探索机制、Trigger 卡片与 MVP 技术验证]]。字段契约见 [Trigger Schema v0.2](Trigger%20Schema%20v0.2.json)。本轮验证以文本为主。

## 主对话与卡片

打开项目总览可进入 README 主讨论，按需查看本项目的 Markdown。进入任务说明后可在该任务的主讨论中执行。只有出现值得继续推进的行动或判断才建候选；普通提问直接回答。已有候选优先按 ID 更新，改变标题时继续用原 ID。多个主题各自更新。缺口影响下一步时在当前对话追问。卡片的意图和背景均属 Agent 当前的理解；点「看原话」查看带消息序号的用户原文。

点击「创建任务」或「确认里程碑」会按卡片当前内容写入项目，成功后记录目标笔记路径。写入失败时保留候选，可以修订后重试。点击「忽略」保留关闭记录。主对话也支持「创建任务：标题」「确认里程碑：标题」「忽略：标题」；模型调用候选工具时，服务端核对本会话最新用户原话与标题。对普通自然语言，模型仍需要自行识别意图；卡片按钮提供确定的人工操作。候选保存在 DS Bot 会话，正式结果保存在项目 Markdown。

## 回放用例

按顺序在同一项目主对话发言，逐轮记录实际卡片数、ID、来源序号和是否产生文件。表中答案是预期行为，仅用于实验标注。

|场景|输入及来源|预期观察|
|---|---|---|
|模糊探索|「我担心自己在重复造轮子。」（V0.4 记载的原话）|可以先讨论、追问；不直接建立研究任务。|
|提出探索方向|「我现在需要研究一下 DSH。」（本次 Handoff 示例）|出现行动候选；若目的不充分，主对话中澄清。|
|澄清范围|「先只评估它的插件接口。」（模拟续句）|更新上一张卡，引用两轮来源。|
|改变方向|「我还有一个思路，能否对dsbot这个插件，做改造」（本线程原话）|辨别是在调整同一个目标，还是另起探索；不因换词复制卡片。|
|补充隐含意图|「对就是给dsbot加一个工作台，用于跑我的这套流程」（本线程原话）|同一候选的意图更具体；这句本身没有确认任何技术结论。|
|第二条认知线索|「我还想弄清一份文档能不能保留独立会话。」（模拟）|可以并存第二候选；两者分别保留出处。|
|普通问答|「现在这个h5本地存放在哪里」（本线程原话）|回答位置，卡片数和正式对象数不变。|
|撤回|「忽略：〈第二张卡的完整标题〉」（模拟，替换占位符）|只关闭该卡。重复处置不新建文件。|
|明确行动|「创建任务：评估插件接口」（模拟）|一份正式任务；卡片指向任务 Markdown。|
|确认后沉淀|「确认里程碑：每份文档保留独立会话」（模拟）|写入一条里程碑，保留会话与依据序号；若缺乏明确确认，停在候选。|

## 实验记录口径

逐轮记录应识别但遗漏、普通问答误触发、重复卡、错误更新其他卡、修正未生效、未经确认写入及目标链接失效。暂不设通过率阈值。脚本模型用于验证工具和界面；真实 DeepSeek 对这些话语的判读需要单独记录。当前不裁定索引方案、归档期限或字段级置信度。
