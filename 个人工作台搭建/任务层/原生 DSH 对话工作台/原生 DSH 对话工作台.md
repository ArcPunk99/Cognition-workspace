# 原生 DSH 对话工作台

**目的**　在项目、任务和文档中按需建立 DSH 对话，让每次讨论围绕所选工作的上下文推进。

**来源与上下文**　承接 [[DSH 插件 MVP]] 的 Trigger 实验。此版使用 DSH 原生 Session、聊天输入框和模型设置。项目文件沿用本地 Obsidian 工作台。

**目标**　同一任务可手动开启多段独立对话，一轮可以提出多个并列候选。每张卡都可以单独处置和回溯。

## 启动与试用

双击同目录的「启动原生工作台.cmd」。看板服务使用 48732，独立 DSH 工作台使用 48733。首次启动会打开 DSH 浏览器页面；如有预览版说明，点「继续」，再点「项目工作台」。

1. 打开项目总览、任务说明或 Markdown 文档。右侧可选择旧讨论，或点「＋ 新对话」填写主题，点击「创建并进入」。只有创建操作会新建 Session。
2. 展开「已注入的上下文」查看来源清单。新会话读取任务说明、当前文档、可唯一解析的相关双链和同任务目录下的 Markdown。快照最多 10 份、合计 18,000 字符；后续改动可通过新开讨论重新读取。
3. 直接在 DSH 输入框中讨论。可用“两条不同的待办，再加一条判断”试验同轮多候选；实际识别效果随所选模型而变。
4. 展开卡片看原话，创建任务、确认里程碑或取消。已取消的卡片可以恢复成候选。转化成功后可打开目标笔记。
5. 看板顶部「创建任务」可直接手工建任务。选中任务后，「删除任务」会显示待删除任务的名称，点击「移入回收站」后移动整个目录。「任务回收站」可恢复目录；遇到同名目录会保留双方。历史 DSH 会话继续保留。

独立配置名为 personal-workspace。插件源码在 plugin 目录，安装包为 personal-workspace-native-0.1.1.tgz。原生会话由 DSH 保存，插件只另存上下文快照、任务关联和 Trigger。此版已用真实 DSH 与脚本模型验证流程，尚待使用者检验真实模型在连续讨论中的判断质量。
