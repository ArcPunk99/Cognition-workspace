# Personal Workspace — Milestone 确认与 Handoff

**日期**：2026-11-24  
**范围**：本轮关于论文阅读、Task 生命周期、多 Agent 协作与原始资料管理的讨论  
**状态**：以下为本轮确认的设计共识；未决问题单列，不视为已确认。

## 一、已确认的 Milestones

### M01｜Milestone 与任务交付解耦
Milestone 记录人在阅读、探索和讨论中形成并确认、具有持续价值的认知增量。它不必直接帮助当前 Task，也不必进入最终 Deliverable。Task、Milestone、Deliverable 是不同对象。

### M02｜Milestone 是长期认知资产
Project/Task 归档不意味着 Milestone 失效。所有已确认的 Milestone 可在未来知识库中检索、引用、复用；保留原始任务、资料及形成依据。跨项目知识库的具体组织方式暂不展开。

### M03｜AI 导读不等于人的认知确认
外部原始资料完整保留；AI 可以压缩、提炼、导航阅读，但摘要不能代替原文，也不能自动成为用户认可的 Milestone。Milestone 需要人阅读、理解并确认。

### M04｜任务价值判断与认知价值判断分离
确认 Milestone 的认知价值，不等于确认其对当前任务有用。人在意图层判断哪些认知支持当前任务，以及任务目标是否已经满足。排除性结论也可能构成有效任务成果。

### M05｜Task 生命周期由人的意图驱动
Task 通常产生阶段产物，但阶段产物不自动触发完成。人可以继续原 Task、派生关联子 Task，或确认任务完成。创建子 Task 不要求父 Task 已完成；无需因阶段产物增加状态机状态。

### M06｜意图可在对话中逐步形成和演进
任务的目标、需求、假设可能在前几轮对话逐渐浮现，也可能在执行中变化。意图影响 Task 创建、延续、派生和结束，但不要求 AI 全程监控或自动拆分；最终判断由人作出。

### M07｜稳定工作台优先于复杂 Agent 自动切换
个人 Workspace 的主要执行/对话角色倾向由 DeepSeek 承担。用户可在 GPT、Codex 等外部环境完成讨论或工作，再通过链接、附件或 Handoff 将结果引入当前 Task。MVP 不必先实现复杂的多模型 Router。

### M08｜Task 是稳定的工作载体
外部 Agent 可更换，但 Task 的目标、状态、认知资产、资料和产物关联应保持连续。平台主要负责组织和衔接，而非替用户做全部调度决策。

### M09｜Task 工作区支持多类型外部输入
每个 Task 都有资料入口，支持 PDF、Markdown、外部对话链接、Handoff 等。外部 GPT 对话应尽可能转换为可保存的完整 Markdown；若无法获取全量内容，须标明缺失，不可假称完整。

### M10｜入库与加入对话上下文分离
上传资料后可以选择仅入库，或用于当前对话。仅入库的资料作为 Task 资产保留，后续通过索引及用户指令按需调用；不默认把全部文件塞进模型上下文。

### M11｜Task 资料以目录/路径索引
Task 可按文件夹理解，资料通过稳定的目录路径或索引定位。Agent 根据索引读取指定资料，不依赖对“刚才那份”的模糊猜测。优先复用现有目录和文件能力，不额外发明复杂索引系统。

### M12｜原始资料完整保存、可溯源
论文、外部对话、手写 MD 等应尽可能保留全量原始上下文和来源信息。AI 摘要、Milestone、工作产物不能替代原始资料。以 Task 为单位应能汇集和调取其相关原始资料，形成 Case Library 视图。

### M13｜统一 Raw 库与 Task 索引分离（当前倾向）
倾向统一保存原始资料，由 Task 索引关联与引用；避免同一资料跨 Task 重复复制。物理存储位置与工作归属分离。这是当前偏好的架构方向，具体实现尚未最终选型。

## 二、当前流程草案

1. 人在对话中逐步明确意图、目标与 Task。
2. 在 Task 中上传原始资料或外部协作 Handoff，先完整入库并建立索引。
3. 用户按需指定资料进入对话；AI 可辅助导读、探索、执行。
4. 人阅读并确认有长期价值的认知，形成 Milestone；工作过程中另可形成 Artifact。
5. 人在意图层判断 Milestone 对任务的作用、目标达成情况。
6. 由人决定继续当前 Task、派生子 Task 或完成归档。
7. 后续 Task 可引用已确认认知和相关原始资料，按需加载上下文。

## 三、对象边界

| 对象 | 核心职责 | 不应混同于 |
|---|---|---|
| Task | 承载意图、目标、执行与状态 | 文件本身或某次 Agent 会话 |
| Raw | 完整原始资料及来源 | AI 摘要、认知结论 |
| Conversation | 探索、讨论、协作过程 | 最终确认的知识 |
| Milestone | 人确认的长期认知增量 | 必须交付的任务产物 |
| Artifact / Deliverable | 阶段性或最终工作产物 | Milestone |
| Index | 定位 Task 相关资料 | 将全部资料自动加载到上下文 |

## 四、待讨论／不应误写为已定

- 子 Task 是否默认继承父 Task 的全部资料访问权；当前建议是可追溯引用、不自动复制、不自动全部加载，尚未得到明确确认。
- 统一 Raw 库的物理实现、路径规范、标签体系、去重与版本控制。
- 外部对话链接的抓取权限、可导出性、完整性校验与失败回退。
- 意图层交互的具体 UI、Task 创建/派生判定规则、最小状态机字段。
- 全局知识库与跨 Project 认知图谱的组织机制，暂缓讨论。

## 五、下一轮 Handoff 建议

**当前讨论焦点**：收敛 Task 生命周期与资料管理的 MVP 交互，避免过度设计。

**已固定的前提**：人主导意图与任务判断；Milestone 与交付分离；原始资料完整可溯源；资料入库不等于加入上下文；Task 有稳定索引；外部 Agent 通过资料/Handoff 接入。

**建议下一问题**：先用一个具体 Task（例如阅读一篇论文并形成设计判断）走通“资料导入 → 索引 → 按需阅读 → Milestone → Artifact → 人工决定继续/派生/完成”的端到端流程，再确定必须实现的 UI 和数据字段。

**注意**：此文档是讨论共识的 Handoff，不是外部论文或 GPT 对话的原始全文备份。
