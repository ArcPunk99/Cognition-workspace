# 项目如何同时推进任务与形成认知

做「个人工作台搭建」这件事时，有两个问题一直交织在一起：工作怎么往前推，工作中想明白的东西怎么留下来。最初想做的是一个能接手的项目空间：打开它能找到当前任务，换一个 Agent 也能知道上次做到哪里。讨论到一半，扭老板问，自己会不会在重复发明别人已经做过的东西。就是这句话，改变了下一步要做的事。[《构建个人工作台框架》原对话](https://chatgpt.com/c/6b0163f0-51b0-83e8-aba1-a5dd397ca664) · [[Personal Workspace Handoff V0.4#阶段 A：问题出现|V0.4 记下的起点]]

## 一个疑问改变了下一步行动

沿着原来的思路，接下来可以继续定目录、写字段。可如果已有理论或工具已经解决了其中一部分，那么在决定怎么搭之前，得先弄清哪些可以借用。对话里于是出现了 BDI、LangGraph 等研究线索。**搭工作台的意图还在，眼前的行动多了一步：找资料来检验设计。** 这里发生的是探索方向的变化，当时没有把它另立为正式 Goal。[[Personal Workspace Handoff V0.4#阶段 B：资料发现|原交接中的研究线索]]

这段讨论还产生了一个实际交付。扭老板请对话 Agent 整理 Handoff 给 Codex，理由是「否则他根本就不了解现在目前为止我们想做什么」。V0.4 把问题、已确认要求和待研究的事项交给下一位执行者。同一份文件，对前一场讨论是产物，到了本地项目又成为有出处的 Raw。只保存一份，就能从两头引用。[《构建个人工作台框架》原对话](https://chatgpt.com/c/6b0163f0-51b0-83e8-aba1-a5dd397ca664) · [[Personal Workspace Handoff V0.4|本地收到的交接材料]]

## 查资料这件事，又改变了对工作台的要求

对话 Agent 列出研究方向后，扭老板指出，还要亲自看这些材料，才能判断哪些话值得留下。此时暴露出一个仅看任务状态看不见的问题：即使「查找资料」已经做完，接手的人仍得分清，哪些只是 Agent 找到的线索，哪一段确实经人审阅，哪一句判断获得了确认。这次讨论由此形成了一个明确要求，即 **MS-001「认知形成过程必须完整可追溯」**。到今天还能从里程碑页点回交接材料里的确认句。[[MS-001 认知形成过程必须完整可追溯]] · [[Personal Workspace Handoff V0.4#^ms-001-confirmed|确认原文]]

这个区别已经体现在后续工作里。BDI 综述被收入 Raw，有了中文译稿，也做了与工作台三层职责的对照。它推进了研究，给人留下了可读的材料；库里这篇论文的人工审阅范围仍未记录。「哪些机制值得复用」也仍由扭老板判断。资料到手、成果做出、判断成立，各有自己的依据。[[BDI Agent Architectures - A Survey (IJCAI 2020).md|BDI 论文与阅读入口]] · [[BDI 智能体架构综述（中文译稿）|中文译稿]]

## 产物让一个判断有机会接受检验

本地后续搭出的 Bases 进度表提供了另一个例子。原先的设想是，项目页能看任务，里程碑能回到证据。等表真正做出来，Codex 从表里点开任务，核对状态，再从 MS-001 点到 V0.4 第三节，看见对应句子高亮。这个产物给出的反馈很具体：这两条路径在本库跑通了。随后扭老板确认收尾，任务才记为「已完成」。任务页保留了测试时的「进行中」，笔记属性则记录当前状态。[[验证能否按项目查看任务#实测记录 · 2026-11-22|任务实测记录]] · [[个人工作台搭建进度.base|当前进度表]]

回看这一轮，**意图**解释为什么搭工作台，**认知**影响接下来该查什么、哪些依据值得保留，**行动**把设想变成能读、能点、能核对的东西。**产物**交给下一位使用者，又提供了检验原判断的机会。项目因此既能向前交付，也能留下「我们为什么走到这一步」。这些是同一段工作的不同侧面，可以沿链接来回读。

反馈也可能一路回到最初的意图。举个仍待验证的情形：如果下一份实测报告表明现成组件足以承担某项功能，扭老板可以保留原目标，把实现策略改为集成；也可以决定缩小本期目标，把这项功能留给以后。这两个决定会产生不同的任务。报告提供调整的理由，哪条路成为项目的新方向，要等人作出决定。[[Personal Workspace Handoff V0.4#阶段 E：认知影响意图|交接中设想的目标调整情形]]
